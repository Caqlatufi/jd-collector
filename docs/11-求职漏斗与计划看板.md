# 求职漏斗与计划看板

展示求职漏斗、按月投递进度时间图、当天高亮及无反馈/超期异常；直接通过节点弹窗维护进度和面试。实际求职节奏另见[求职冲刺计划](12-求职冲刺计划.md)，其中的周目标不会自动变成日历任务。

## 1. 需求分析

### 背景、目标与对象

候选人需要一个每日入口同时观察求职漏斗和整月计划，并突出当天与异常。

### v0.1 范围与核心需求

漏斗、整月时间图、月份切换、回到今天、异常筛选和等级统计。

### 边界、后台与兼容

时间表是进度操作主入口；弹窗调用pipeline/interview既有领域接口，不直接写表。记录实际投递日期后自动生成投递标记，不再要求填写下一步；未投递岗位不生成投递标记。同一岗位一行，按日期保留投递、阶段变化、各轮面试和当前跟进安排；同一天多个节点纵向排列并可分别查看。取消面试保留为灰色历史节点。取消旧四卡片、独立阶段统计和七日面试区；接口旧字段暂兼容。

投递严格超过14天且没有已记录反馈时，显示TIMED_OUT「超时」并置灰，不再计入待处理异常；14天观察节点保留在截止日。反馈以HR沟通、笔试、面试、Offer、接受/拒绝的当前阶段或历史阶段事件，以及未删除的面试记录为依据；仅修改JD、评分、备注、跟进计划或重复保存APPLIED不算反馈。收到首次反馈后停止该无反馈提醒，不按后续阶段重新计14天。拒绝、接受、撤回、关闭保留投递历史但停止提醒；归档岗位排除。投递后的评分档位变化不抹去投递事实。

### 成功标准与工作量

数量真实、今天醒目、异常明确、事项不重复，预计 1 日。

## 2. 架构设计

### 架构与链路

```text
jd_posting + jd_stage_event + jd_interview
          -> DashboardService 实时聚合
          -> conversion + planItems + tierCounts
          -> 漏斗 + 整月时间图 + 异常筛选
```

### 规则与模型

`PlanItem`：id、postingId、interviewId?、companyName、jobTitle、tier、kind(APPLICATION/FOLLOW_UP/INTERVIEW/STAGE)、title、description、scheduledAt?、status、feedbackDueAt?、elapsedDays?。APPLICATION的scheduledAt采用真实appliedAt，feedbackDueAt=appliedAt+14天，elapsedDays为投递后完整天数，不读取updatedAt计时。

状态：PLANNED未来/今日、OVERDUE逾期、COMPLETED完成、UNSCHEDULED有动作无时间、NO_SHOW爽约。CANCELLED已取消、ENDED流程已结束（保留原日程但不再催办）；面试同步动作去重。漏斗按岗位/阶段事件唯一 ID 计数，零分母比率为0。

投递状态：WAITING_FEEDBACK等待反馈、TIMED_OUT超过14天无反馈（超时）、FEEDBACK_RECEIVED已有反馈、ENDED被拒/撤回/关闭，COMPLETED接受完成。按Asia/Shanghai服务端时钟比较，刚满14天仍等待，严格超过观察点才异常；不新增表、定时写入或自动阶段流转。被拒/撤回/关闭/超时为灰色，接受完成为绿色；等待投递蓝色，面试紫色，实际逾期事项红色。超时是实时派生显示状态，保留原业务阶段，晚到反馈仍可继续推进。

### 目录与存储

图例：`[+]` 新增，`[~]` 修改，`[-]` 删除。
`backend/dashboard/src/main/java/com/jd/dashboard/{[~] ctrl,model,service}`；`frontend/src/dashboard/{[~] api,pages,index.ts}`。无独立表或迁移。

## 3. 开发方案

### 目标、依赖与顺序

交付实时聚合和首页：漏斗查询 → 计划映射/去重/状态 → 接口 → 时间图。依赖 posting、pipeline、interview。

### 接口与字段

`GET /jd-collector/api/dashboard/today` 无参数。返回：`conversion`（collected/applied/hrScreen/interviewed/offered及三项比率）、`planItems`、`tierCounts`、`serverNow`；兼容返回 todayActions、overdueActions、nextSevenDayInterviews、stageCounts。

时间图右上角在月份导航前提供单选「进度类型」，默认「进行中」。被拒、主动终止、关闭、取消、超时及已接受等结束类型默认隐藏；只有明确选择「超时」才展示超时岗位，不提供会混入超时的「全部」选项。类型按岗位当前状态判断，旧的取消面试不遮掉仍有有效面试的岗位。表格、当天安排、节点数量、异常数量统一使用同一筛选；选中岗位后保留完整历史，类型切换重置只看异常，月份切换和回到今天保留所选类型，刷新页面回到进行中，路由定位不会绕过筛选。

时间图突出今天，支持月份切换和只看OVERDUE/UNSCHEDULED/NO_SHOW。浅色区间从投递日期延伸至最新进度（等待/超时延伸至14天截止日），使用最后动作颜色的15%透明度；已终止流程仍保留连续灰色色带。今天整列保持橘色。投递、各阶段、各轮面试按原始日期保留，同日节点分别操作；创建面试的系统阶段事件去重。

点击节点打开「更新求职进度」，分「下一步动作」和「修改本条记录」。前者支持被拒、安排面试（必填时间）、完成本轮、下一轮、Offer及接受/放弃；后者支持投递时间纠正、面试改期/状态/问题/反馈/复盘、阶段时间及备注、跟进动作。加载失败可重试，保存失败保留输入，保存期间禁用重复操作；成功刷新看板。删除面试一级tab，旧/interviews路径重定向时间表，面试API和数据继续保留。

投递日期使用PUT /postings/{id}/application-date，expectedAppliedAt与appliedAt必填，锁岗位并校验原值；不改变阶段、简历和阶段历史。日期不能晚于现在或已记录的后续阶段。阶段记录使用PUT /postings/{id}/events/{eventId}，校验归属和expectedOccurredAt，只修改时间及备注，不新增阶段流转。

### 风险与完成

风险为重复事项、时区边界和漏斗重复计数。以服务端时间、唯一岗位和 interviewId 去重。页面与数据库一致即完成。
