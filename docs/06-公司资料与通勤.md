# 公司资料与通勤

维护公司资料、办公点、通勤依据和公司质量；不负责JD正文识别、岗位评分或投递状态。与[JD管理与评分](05-JD管理与评分.md)协作，不把总部地址自动当作岗位办公点。

## 1. 需求分析

### 背景、目标与对象

公司属性、办公点和通勤会被多个 JD 复用。候选人维护一次，JD 收集和评分统一消费。

### v0.1 范围与核心需求

- 新增、编辑、查看、搜索公司。
- 维护名称、别名、业务属性、产品所有权、地址、通勤、质量和备注。
- 为 JD 提供公司选择和名称展示。
- 公司级官网投递渠道维护一次供多个 JD 复用；只填写核实过的官方招聘页或官网指向的招聘站，未确认留空，证据和邮箱记录在研究备注中。公司渠道存在不代表某条 JD 官网同步。

### 本期边界与能力边界

- 不保存 JD、阶段、简历或面试。
- 公司库提供“公司列表 / 上海地图”切换，只展示上海市底图；支持同一公司维护多个工作地点，汇总公司办公地址与未删除 JD 的地点，不用总部地址覆盖岗位办公点。
- 底图随前端打包，无需地图 Key；用户点击“匹配地图坐标”时通过 Photon 匹配已有详细地址的楼宇/园区，串行限速并缓存结果。地址不完整时显示区域参考或待补充，不能把行政区中心伪装成具体办公楼；地图不计算通勤。
- 上海道路以本地 GeoJSON 随应用发布，保留真实道路折线、道路等级及路名；全市显示主干路，放大逐步显示街道和支路，可开关道路图层。查看路网不请求在线地图或瓦片服务。
- 公司初评不覆盖岗位保存时的公司分。
- 不物理删除，停用后不供新 JD 选择。

### 后台范围与兼容策略

公司页提供搜索、新增、编辑和上海地图。列表按页读完全部公司，不能只取前100家。通勤基准与时间要求由本地 JD 门槛配置；办公点变化时维护多个工作地点并在备注保留背景，历史岗位不自动重算。

### 成功标准与工作量

资料可复用、名称不重复、范围合法、历史关联不丢失；预计 0.5–1 个开发日。

## 2. 架构设计

### 总体架构与链路

```text
frontend/company -> company Controller -> Service -> Repository -> jd_company
posting ----------------------------------------------------------^ companyId
录入 -> 标准化名称 -> 唯一性/范围校验 -> 保存 -> JD 选择
```

### 规则矩阵

| 规则 | 口径 |
| --- | --- |
| 名称 | 去空格后非空，忽略大小写唯一 |
| 通勤/质量 | 0–300 分钟；0–20 分 |
| 启用 | 默认 true；停用不破坏历史 |

### 核心数据模型

| 字段 | 类型 | 必填 | 用途/约束 |
| --- | --- | --- | --- |
| `name/alias` | String(120) | 名称是 | 正式名/简称 |
| `businessType` | Enum | 是 | PRODUCT、TO_B_PRODUCT、DELIVERY、OUTSOURCING、UNKNOWN |
| `productOwnership` | Enum | 是 | HIGH、MEDIUM、LOW、UNKNOWN |
| `address` | String(255) | 否 | 兼容原办公地址，地图与多地点一起去重汇总 |
| `workLocations` | List，最多50个 | 否 | 每项包含地点名称≤120、地址必填≤255、可选WGS84经纬度；经纬度必须同时填写 |
| `officialApplicationUrl` | String(2048) | 否 | HTTP/HTTPS 官方投递渠道，拒绝脚本链接和带账号的 URL |
| `commuteMinutes/qualityScore` | Integer | 否 | 0–300 / 0–20 |
| `notes` | Text | 否 | 路线、搬迁、业务研究 |
| `active` | Boolean | 是 | 新数据可选性 |

### 目录、职责与存储

图例：`[+]` 新增，`[~]` 修改，`[-]` 删除。

```text
backend/company/src/main/java/com/jd/company/{[~] ctrl,model,repo,service}
frontend/src/company/{[~] api,pages,index.ts}
```

公司主资料归属 `jd_company`，多地点按顺序存储于 `jd_company_work_location`，地图匹配缓存位于 `jd_company_location_cache`。均由 JPA DDL 管理；只新增 jd_ 表，不操作 aic_ 表，不使用迁移脚本。

## 3. 开发方案

### 目标、范围与顺序

交付公司 CRUD、搜索和 JD 选择：实体/Repository → Service 校验 → Controller → 公司页面 → JD 联动。

### 职责、边界与依赖

公司功能拥有公司数据和唯一性规则，依赖公共基础能力；posting 只通过 `companyId` 和公开查询交互，不在本功能处理岗位评分。

### 数据模型

保存字段：`name`必填≤120、`alias`≤120、`businessType/productOwnership`必填、`address`≤255、`commuteMinutes` 0–300、`qualityScore` 0–20、`notes`、`active`。响应增加 `id/createdAt/updatedAt`。

新增可选 `officialApplicationUrl`≤2048：去首尾空格，空字符串清空；旧客户端遗漏或传 null 时保留现有链接。公司页支持编辑与打开官方招聘，JD 列表按 `companyId` 复用该链接。该字段不替换岗位 `sourceUrl`，不修改 `officialSynchronized` 或投递阶段。

`workLocations` 在旧客户端遗漏或传 null 时保持原值，显式 `[]` 清空多地点；原 `address` 字段独立兼容。公司保存事务同时更新多地点，非法数据不得部分落库。上海地图汇总三类来源：手动工作地点、原公司地址、JD地址；同公司相同地址合并来源，不同办公点分别保留，仅写“上海”的重复市级记录不额外冒充办公点。

地图坐标优先使用显式WGS84标注，其次使用楼宇/门牌名匹配结果；坐标经上海行政区多边形校验，外地地点隐藏。底图采用正北朝上的二维墨卡托投影，按投影比例居中适配画布，不随宽高拉伸；行政区边界、地点标记和公司聚焦统一使用同一投影。仅知道区名的地址使用灰色菱形区域参考；没有区名且未能匹配的地址进入待补充清单，不补造经纬度。重合点合并显示地点数，点击可查看组内所有地点；点击公司可以突出其多个办公点。支持公司/地址搜索、行政区筛选、定位状态筛选、拖拽缩放及全上海复位。

Photon 外部请求单线程、间隔至少1100毫秒；成功结果缓存，空结果缓存7天，网络失败不记为成功。只接受上海州/市范围内且名称或街道门牌匹配的结果，前端再次检查上海市界；匹配地点是参考结果，不代表招聘方确认。可通过 `jd-collector.company.geocoder-url` 切换自建 Photon 兼容服务。外部请求期间不持有数据库事务，页面关闭后停止后续队列，失败时保留离线底图与区域分布。

本地道路来自 [Geofabrik 上海 OSM SHP 数据](https://download.geofabrik.de/asia/china/shanghai.html)，生成文件为 `frontend/src/company/assets/shanghai-roads.geojson`，按上海区划边界裁剪，使用 WGS84 经纬度，约一米容差简化折线。仅包含已有的可驾车道路分类，不臆造道路，不将街道办事处边界或地址文字转换成虚构道路。配套 `shanghai-roads.metadata.json` 保存来源、归档时间、SHA-256、道路分类数量和 ODbL 许可；页面保留 [OSM 署名与许可链接](https://www.openstreetmap.org/copyright)。它是显示数据，不包含路线计算所需的完整通行限制与拓扑。

道路按缩放倍数分级：小于2显示高速/快速路/主要干道，2起增加次干道，5起增加普通街道，10起增加支路；仅渲染当前视口附近的道路。路名在屏幕空间去重和避让公司标记，最多45个，滚轮、拖动、窗口缩放、聚焦公司及“全上海”复位后同步更新。道路不可点击，不拦截公司标记；公司搜索不会隐藏道路。道路加载失败显示独立重试入口，不阻断公司地点与行政区底图。

更新数据时，在项目根目录使用独立 Python 环境安装 `ops/maps/requirements.txt`，执行 `python ops/maps/build-shanghai-roads.py --download`；原始压缩包存放 `runtime/maps`，不提交。已有压缩包可省略 `--download`，也可通过 `--source <zip路径>` 指定归档。生成后执行前端构建和道路/地点 Electron 验收，再打包本地服务。日常打开地图不运行生成脚本。

### 公司地址补全

地图每个公司地点提供“补全地址”，“地址查询任务”可查看后台进度。任务复用 `ops/jd-import` 的 LangGraph、FileCheckpointer、原生后台截图/滚动和只读模型节点，默认 Astra/medium；关闭弹窗后继续，登录/验证可暂停接续。同公司未完成任务按公司ID去重，重启后文件队列和检查点保留。

先读取该公司JD链接并逐页截图找当前岗位的详细工作地址；确认官网岗位页无详细地址时，直接转入公司在上海的办公地址搜索；没有JD链接时直接搜索公司。JD证据必须对应当前公司和岗位；公司搜索结果保留为公司地址参考，不能作为该JD的工作地址。只知道城市/行政区、仅有注册地址、公司身份不确定或地址冲突时进入待核实，不猜测门牌或经纬度。

地址证据存储于 `jd_company_address_discovery`，包含公司/岗位、地址、来源URL、截图证据引用及任务ID。同公司同岗位同地址幂等保存，不覆盖公司原资料和其他办公点；经核实的JD地址仅更新该岗位的 `location`，保存时核对原链接和原地址，其他评分、正文与阶段保留。地图合并来源并可打开证据。地址保存后可选匹配地图坐标，匹配失败不回滚已确认的地址。

接口：`POST /api/company-address-tasks {companyId}`，`GET /api/company-address-tasks`、`GET /api/company-address-tasks/{id}`、`POST /api/company-address-tasks/{id}/retry`；证据读取 `GET /api/companies/address-discoveries`，公司参考写入 `POST /api/companies/{id}/address-discoveries`，岗位地址写入 `POST /api/postings/{id}/address-discoveries`。队列位于 `runtime/company-addresses`；不是新的数据库任务系统。地址后台标签采用 `company-address:<uuid>`，需客户端 `WEB info` 返回 `companyAddressCapture=true`；旧客户端提示保存输入并重启后继续。

底图来源：[阿里云DataV上海行政区GeoJSON](https://geo.datav.aliyun.com/areas_v3/bound/310000_full.json)，仅包含上海16区；地点数据注明 © OpenStreetMap contributors / Photon。匹配服务使用限制见 [Photon项目说明](https://github.com/komoot/photon#demo-server)，保持低频本机单用户用途，不批量抓取整个城市POI。

### 接口

| 方法 | 路径 | 请求 | 返回 |
| --- | --- | --- | --- |
| GET | `/jd-collector/api/companies` | `keyword,number=1,size=20`，size≤100 | 分页公司 |
| GET | `/jd-collector/api/companies/{id}` | ID | 公司详情 |
| POST | `/jd-collector/api/companies` | 保存字段 | 新公司 |
| PUT | `/jd-collector/api/companies/{id}` | ID+保存字段 | 更新结果 |
| GET | `/jd-collector/api/postings/work-locations` | 无分页；仅地点所需字段 | 未删除JD的 postingId/companyId/address |
| GET | `/jd-collector/api/companies/location-positions` | 无 | 本地地址坐标缓存 |
| POST | `/jd-collector/api/companies/location-positions` | `{address}`，非空≤255 | 匹配结果或无匹配；服务异常返回502，不修改公司/JD |

错误：40001 字段非法，40401 不存在，40901 名称重复。随一体化应用部署；办公点过期通过研究备注控制。

### 完成标志

公司可维护、搜索、停用和复用，JD 能稳定显示公司名。
