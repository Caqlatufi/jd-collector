# 打招呼用语生成

## 需求分析

JD 列表的每行操作增加“打招呼”。用户选择本次沟通使用的启用简历，以当前保存的 JD 原文和所选简历完整正文生成首次聊天消息。目标是让 HR 快速看到最相关的真实经历，愿意查看简历、继续沟通。

生成成功并校验通过后自动保存到数据库。再次打开岗位时直接恢复最近生成的正文、简历版本与生成时匹配依据；切换简历时读取该岗位与该版本最近的结果，无记录时等待用户生成。每次重新生成成功新增一条记录，失败不覆盖历史。简历停用、归档或正文发生变化后，历史结果仍作为生成时快照可读；重新生成要求选择当前可用简历。文本框临时编辑仅用于本次复制，不自动覆盖已保存的模型结果。更新前仅在旧弹窗内存在且已关闭的结果无法自动恢复。

弹窗底部在“关闭”左侧提供“已发送消息”。用户自行发送后点击，即记录该岗位进度为“已发消息未回复”（MESSAGE_SENT）；无需先选择简历、生成或复制用语。保存成功关闭弹窗并同步列表、详情及阶段筛选；失败保留弹窗与已生成/编辑正文，回读最新阶段后允许重试。保存期间禁用重复点击及弹窗操作。已处于 MESSAGE_SENT 或已实际投递的岗位禁用此按钮，避免重复记录或回退投递阶段。按钮只记录用户确认的进度，不调用招聘平台发送消息。

固定使用 `gpt-6.1-sol`、`medium`，提示词保持100–500字中文消息要求，信息充分时建议300–450字；500字作为生成目标上限，不作为展示和复制的硬拦截。结构为“经验摘要 → 任职资格逐项对应 → 加分项逐项对应 → 简短结束语”，每项一行，先写JD要求的简短名称，再写简历中的实际项目、职责或成果；按JD原顺序列出最多10个有事实依据的符合项。任职资格和加分项之间留一个空行，开头及结束语与匹配分组之间也各留一个空行。加分项不存在或无事实依据时省略该分组；任职资格未单列时对照明确的岗位要求或职责，不强行凑项。

开头优先直接复用传入简历“个人概述”的第一段正文；列表形式取第一条完整列表项，排版折行仍视为同一段。仅去掉标题、列表标记和Markdown排版标记，并将段内换行合并为一行，其余文字、标点、数字及顺序保持原文，不改写、删句或拼接后续段落，不按JD重新挑选摘要。篇幅需要压缩时调整后续匹配条目，不截短该段。

只有“个人概述”章节缺失或第一段正文为空时，才按简历和JD生成1–3个短句的经验摘要：首句直接展示可证明的研发年限、技术方向及相关AI经验，后续可概括相关项目、重构、并发/数据库优化或完整交付能力。不固定套用某位候选人的年限和经历，AI辅助开发与AI应用经验分开表述，不相加为总研发年限；没有明确年限不自行推算。两种情况下均不额外添加“您好”“想应聘……岗位”“以下是我的相关经历”等开场白，正文避免重复开头的完整句子。

汉字、英文字符、数字、标点、分组标题和编号按 Unicode 码点计数，空白不计。用户可重新生成、编辑、复制。不足100字仍禁止复制，正文保留；超过500字照常展示全文并允许复制，字数旁显示建议范围，不裁切或自动压缩。文本框自动适应10–18行，保留换行和空行；弹窗居中，长正文在弹窗体内滚动，复制按钮保持可见。生成失败的原因以弹窗内错误提示持续显示，首次失败后按钮显示“重试生成”；开始重试或切换简历时清除旧错误，同一简历重试失败保留已有正文。信息量来自项目背景、本人职责、解决的问题与真实成果，不靠套话或夸大补字数。

不补写简历没有的技能、年限、指标或责任；参与不改为主导，AI 编码工具不改成生产 Agent/RAG 经验，多区域发布不改成多活容灾，项目规模不改成个人吞吐业绩。相关功能见 [JD管理](05-JD管理与评分.md)、[简历版本](07-简历版本管理.md)。生成和复制不发送招聘消息，不创建实际投递或阶段事件。

结合完整项目上下文，选择业务直接相关且本人职责明确的事实，不只按名称或关键词选材；同一项目允许支撑多个要求，不为避免重复改用较弱经历。选择规则通用于各类岗位，不指定公司、项目或某项技能的优先级。首次沟通不写招聘后台可见的毕业院校、学历、姓名、年龄和联系方式，即使JD列有这些要求，也不单列符合项。

时间、数量和成果须绑定原文具体任务：功能改造、模块开发或阶段任务的工期不能扩大为整个项目的交付周期。压缩时保留任务范围，或删去数字；不为突出速度加入无关工期。输出前以对应引用检查动作、责任对象、任务范围和量化结果，保持事实边界。

## 架构设计

- 前端入口为 `PostingsPage`，独立 `PostingGreetingDialog` 承担历史读取、简历选择、生成等待、结果编辑、字数与复制。打开时并行读取启用版本和该岗位最近的结果，优先恢复已保存结果对应的版本；没有结果且岗位引用简历可用时预选该版本，其余情况明确由用户选择。不可用的历史版本保留禁用选项，仍允许查看和复制正文。
- `POST /api/postings/{id}/greeting` 请求为 `{resumeVersionId}`。`posting` 模块通过岗位、简历服务读取已保存事实，生成前完成合法性校验；模型调用不持有数据库事务，校验成功后在短事务内保存结果，入库成功才返回成功，不改变岗位、简历及投递状态。
- `jd_posting_greeting` 由 JPA DDL 创建，继承公共 ID、时间和逻辑删除字段；`postingId`、`resumeVersionId` 为逻辑引用并建立联合索引，`resultJson` 为 LONGTEXT 保存完整响应快照（正文、字数、依据、简历名称/版本、模型与推理强度）。每次成功生成追加一条记录，以 ID 降序读取最近完成保存的结果，不存完整 JD/简历输入。
- `GET /api/postings/{id}/greeting` 不调用模型，返回岗位最近的已保存结果；可选 `resumeVersionId` 限定该简历。无结果返回成功空结果（沿用公共响应空字段省略规则）；岗位不存在返回404。读取不要求原简历仍启用，不重新校验历史引用。
- “已发送消息”由 PostingsPage 复用既有 `PUT /api/postings/{id}/contact-stage`，请求为 `{toStage: 'MESSAGE_SENT', expectedStage: 当前阶段}`；沿用行内进度修改的并发校验、阶段事件、失败回读与筛选同步，不新增接口。简历选择与生成只在弹窗开关或岗位 ID 改变时重置，阶段回读不清除当前草稿。
- 响应含岗位/简历 ID、简历名称/版本、消息、字数、1–10组JD/简历原文匹配依据及固定模型/推理强度。每个编号符合项恰好对应一组依据，顺序与正文一致。后端拒绝不足100字、逐项分组格式错误、分组间缺空行或依据不来自输入原文的结果；不再因超过500字拒绝正常草稿，原有异常结果体积保护保持。错误分别说明字数、格式、依据数量或第几条JD/简历引用不合格，不回显引用正文。统一Windows换行为LF，不截断或自动补写模型消息。引用必须是连续原文，不能拼接不同段落、列表条目或项目；匹配事实需要跨段支持时应精简该条事实。引用校验只验证原文存在，不能替代用户对消息责任范围的复核。
- `CodexGreetingGenerator` 启动 `ops/greeting/worker.mjs`，复用已有 Node/Codex 配置，并按实际 CLI 版本自动定位可执行文件。模型参数在实际 CLI 调用中固定；不读用户配置、execpolicy、项目指令，禁用 shell、网页、MCP、浏览器、插件及多 Agent 能力，不保留会话。资料作为不可信数据提供，不执行其中的指令。

## 开发方案

1. 固定模型和 effort，不沿用截图识别的 Astra 设置，也不在调用失败时切换模型。Node/Codex 路径复用 `jd-collector.recognition` 配置，项目根由 `JD_COLLECTOR_PROJECT_DIR` 指定。显式配置的 Codex 路径优先；未指定时比较本机已安装 CLI 的实际版本号选择最新版本，不能按扩展目录日期数字排序。
2. 模型通过 JSON Schema 输出消息与引用；只用简历作为候选人事实来源，JD 仅用于选择相关经历。临时目录仅放 schema 和最终结果，结束后清理；输入走 UTF-8 stdin，不写常规业务日志。工作进程在内存中限量读取错误事件和 stderr，以最终 `turn.failed` 为首要依据，未收到最终事件时使用最近错误事件或 stderr；不以模型列表刷新警告覆盖最终失败原因。仅返回白名单错误码、已识别的 HTTP 状态和 CLI 退出码，后端转换为中文操作提示，不输出原始认证诊断、Token、助手正文或简历内容。成功结果不会因已恢复的重连事件被当作失败。
3. 单次模型调用上限120秒，后端工作进程等待上限140秒，前端该接口单独使用155秒超时。最多两条生成并发；超时终止进程，不自动重试或按字数二次压缩。CLI 参数或权限不支持时保留失败语义。
4. 历史读取和生成期间锁定选择、重复生成、文本编辑、关闭和复制。请求按弹窗生命周期和读取序号隔离，离开页面后旧结果不回填；更换简历先清空旧消息和依据，再读取对应结果。同一简历重新生成失败保留已编辑的上一条结果。读取失败持续提示并提供重试读取按钮，不自动调用模型。
5. 使用系统剪贴板复制；失败提示用户手动复制。生成结果和依据保存数据库，文本框提示临时编辑的保存边界；依据标注“生成时”，用户编辑消息后不会把依据冒充重新核验结果。
6. 底部“已发送消息”发出类型化事件，由列表提交现有进度接口。成功后才关闭弹窗；相同岗位数据更新同步到弹窗，冲突回读已投递状态后禁用标记。生成中与进度保存中均锁定按钮，复制或生成不会自动触发进度更新。

模型调用失败原因按下表区分，沿用 HTTP 502 / 业务码40002，错误常驻当前弹窗，不添加工作台登录流程或自动切换模型。

| 原因 | 错误码 | 用户提示 |
| --- | --- | --- |
| 模型容量不足 | CODEX_MODEL_CAPACITY | 稍后重试，无需重新登录 |
| 登录凭证失效 / 缺少登录或认证被拒绝 | CODEX_AUTH_EXPIRED / CODEX_AUTH_REQUIRED | 重新登录 / 登录本机 Codex |
| 额度耗尽 / 请求限流 | CODEX_USAGE_LIMIT / CODEX_RATE_LIMIT | 检查用量或等待额度恢复 / 稍后重试 |
| 模型不支持或不可访问 / 权限拒绝 | CODEX_MODEL_UNAVAILABLE / CODEX_PERMISSION_DENIED | 检查模型或账户权限 |
| 上游服务异常 / 连接或响应流异常 | CODEX_SERVER_UNAVAILABLE / CODEX_NETWORK | 稍后重试 / 检查网络或代理 |
| CLI 参数不兼容 / 无法启动CLI | CODEX_ARGUMENTS / CODEX_UNAVAILABLE | 检查CLI版本 / 安装、路径和本机权限 |
| 调用超过120秒 | CODEX_TIMEOUT | 稍后重试；有已识别的上游错误时同时显示该原因 |
| 结果缺失或JSON无效 / 输入格式错误 | INVALID_RESULT / INVALID_INPUT | 重新生成 / 检查JD与简历 |
| 未识别的失败 | CODEX_FAILED | 显示CLI退出码（可得时），不猜测是否登录失效 |
