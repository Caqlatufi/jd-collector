# 工作台启动与导航

负责本地工作台启动、健康检查、顶栏导航、路由刷新和加载已发布页面。桌面窗口和外站标签的独立需求见[桌面浏览器与多标签](02-桌面浏览器与多标签.md)。运行命令及维护操作统一见[项目约定](../AGENTS.md)，本文件不是全项目总架构。

## 1. 需求分析

### 背景与目标

本机单用户工具需要稳定的一体化入口承载各领域，并统一数据库、响应、异常、时区和前端路由。



### 使用对象

候选人通过浏览器或 Electron 桌面入口使用；Codex 负责本地开发、运行和故障定位。



### v0.1 范围

- Spring Boot 入口及业务模块装配。
- Vue 模块注册、顶部导航和 SPA 路由。
- 数据库、时区、JPA 和静态资源配置。
- 统一响应、错误码、异常映射和健康检查。



### 本期边界与能力边界

- 不保存业务数据，不承担领域校验。
- 不建设登录、鉴权、角色、租户和审计。
- 只服务本机；业务模块不得反向依赖 `app`。



### 核心需求与后台范围

| 需求 | 结果 |
| --- | --- |
| 一体化启动 | `7890` 同时提供 API 和前端资源 |
| 模块装配 | 后端 `*Config`、前端 `index.ts` 可挂载 |
| 统一协议 | 普通、分页、异常响应结构一致 |
| 页面入口 | 顶部菜单适配竖屏，刷新业务路由不 404 |
| 可诊断性 | 健康检查返回服务与时间信息 |



### 兼容策略、成功标准与工作量

外部路径固定 `/jd-collector`，时间按 `Asia/Shanghai`；新增模块沿用现有装配协议。冷启动后健康检查和全部路由可用即达标，预计维护 0.5–1 个开发日。



### 工作台刷新

工作台页头提供“刷新工作台”：确认未保存内容可能丢失后，检查本地服务可用再重新加载当前路由，获取服务端已部署的页面。其他招聘标签保持原页面和输入；服务不可用时保留当前页面并提示稍后重试。正式模式按发布后手动刷新，开发模式使用现有 Vite 热更新；Electron 主进程与 preload 更新仍需重启客户端。

## 2. 架构设计

### 总体架构

```text
浏览器 / Electron 工作台 -> frontend/main.ts -> baseInstall + router + 顶部 App
                           -> 业务页面域
              /jd-collector/api
                           ↓
backend/app/Application -> app.Config -> 各领域 *Config
                           ↓ JPA
                      MySQL/MariaDB
```



### 规则矩阵

| 规则 | 口径 |
| --- | --- |
| 服务 | 单进程、多 Gradle 模块 |
| 前端 | 单 SPA、多业务域安装 |
| Electron 入口 | src/app/electron：主进程启动、preload、主窗口生命周期 |
| 公共桌面能力 | src/common/desktop：契约、渲染侧桥接、主进程通用实现 |
| 业务模块 | 依赖公共请求/事件，不反向依赖 app 或直接 import electron |
| 布局 | 顶部导航、竖屏优先 |
| 工作台刷新 | App.vue 的标准页面重新加载；仅当前工作台文档重建，路由保留，外站 view 不受影响 |
| 更新模式 | 正式模式加载服务端构建资源；开发模式由 Vite HMR 更新 Vue；主进程/preload 通过客户端重启加载 |
| 时间 | `Asia/Shanghai` |
| 持久化 | `ddl-auto=update`、`open-in-view=false` |



### 核心模型

本功能无业务表。实体共享 `id: Long`、`createdAt/updatedAt: LocalDateTime`、`deleted: Boolean=false`。



### 核心链路

```text
启动 -> 导入 Config -> 连接数据库 -> 注册 Controller
     -> 提供静态资源 -> SPA 回退 index.html
```

配置、Bean 或数据库失败时直接启动失败。



### 模块目录与职责

图例：`[+]` 新增，`[~]` 修改，`[-]` 删除。

```text
backend
├─ app/src/main/java/com/jd/app/[~] Application.java, Config.java
└─ common/src/main/java/com/jd/{common/exception,system}
frontend/src
├─ app/[~] App.vue, router.ts
├─ common/config/[~] baseInstall.ts
└─ [~] main.ts
```



### 存储边界

无独立表或启动SQL；领域实体由各代码模块通过JPA DDL管理。桌面会话不属于工作台数据库。

## 3. 开发方案

### 开发目标与首批范围

完成后端装配、公共响应与异常、健康检查、前端注册、顶部导航、SPA 回退和本地数据库配置。



### 实施顺序

1. 配置 Gradle composite build 与模块依赖。
2. 建立 `app.Config` 并导入各模块。
3. 配置数据库、JPA、时区和 context path。
4. 实现公共异常与健康检查。
5. 建立前端安装协议、路由和顶部页面壳。



### 实现约束与依赖

| 项 | 值 |
| --- | --- |
| Java/公共层 | Java 17、Spring Boot 3、项目内 `common` 模块 |
| 服务 | `7890`、`/jd-collector`、API `/jd-collector/api` |
| 数据 | MySQL/MariaDB、JPA update |
| 前端 | Vue 3、Vite、Element Plus，多模块入口挂载 |

凭据只从本机配置读取。业务域登记路由，入口统一安装。



### 数据模型与接口

无业务模型。`GET /jd-collector/api/system/health` 无请求参数，`result` 返回 `service/status/framework/timestamp`。

普通响应为 `code/msg/result`；分页响应另含 `page.number/size/totalElements/totalPages`。请求页码从 1 开始，响应从 0 开始。



### 错误码

`40001` 校验失败、`40002` 业务错误、`40401` 不存在、`40901` 冲突、`50001` 内部错误。



### 部署、风险与完成标志

一体化本机运行，Vite 仅开发使用。中文路径异常时通过 ASCII junction 运行 Gradle。健康检查、路由刷新、统一错误和顶部导航可用即完成。



### 刷新行为

App.vue 页头挂载“刷新工作台”按钮（桌面和普通浏览器共用）：ElMessageBox 提示未保存内容会丢失，取消则保留文档；确认后复用 appStore.refreshHealth 检查服务，UP 时调用 window.location.reload() 重新加载当前 URL。检查失败时显示错误并恢复按钮，保留原文档。确认与检查期间禁止重复点击。不新增 Electron IPC、进程重启或定时强制刷新，不清理会话。页面更新前先构建并重启提供静态资源的后端；按钮不会自行编译源码或更新 Electron 壳。

## 4. 验收方案

### 验收范围与非范围

### 前置条件与通过标准

Java 17、Node.js、数据库可用。所有 P0 通过，刷新无 404，失败响应结构一致；构建和真实页面结果分别记录。
