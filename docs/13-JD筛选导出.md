# JD筛选导出

将当前筛选结果下载为CSV，便于表格查看。导出不是全库备份，也不承担恢复；后者见[数据备份与恢复](14-数据备份与恢复.md)。

## 1. 需求分析

### 目标、对象和边界

候选人在JD列表按条件导出岗位；Codex维护过滤、排序、编码和列结构。范围为复用现有筛选生成CSV，包含公司、岗位、评分、阶段、简历引用和下一步信息。只读导出不改变JD、Pipeline或面试，不新增定时任务、云同步、Excel专属格式或数据恢复接口。

成功标准为导出内容与筛选列表一致，评分降序、中文不乱码、引号和换行不串列。原导出与备份合计估算为0.5日，拆分文档不重复计算工作量或新增开发范围。

## 2. 架构设计

### 链路

```text
JD筛选 → ExportController → ExportService
                          └─ posting查询 + company/resume关联
                             → UTF-8 BOM CSV → 浏览器下载
```

### 规则与导出模型

CSV 与列表过滤、评分排序一致；文本双引号包裹，内部引号双写，空值为空字符串。19列：公司、岗位、方向、来源、链接、地点、薪资下限K、薪资上限K、薪资月数、总分、等级、风险、建议动作、阶段、简历版本、投递时间、下一步、下一步时间、更新时间。



### 目录与存储

backend/export/src/main/java/com/jd/export/{ctrl,service}负责CSV响应；frontend/src/posting复用当前筛选参数发起下载。无新表和迁移；读取岗位的逻辑删除、排序与过滤口径与[JD管理](05-JD管理与评分.md)一致。

## 3. 开发方案

### 实施顺序与依赖

复用posting查询 → 转义/BOM/文件名 → 前端下载 → 校验边界数据。依赖posting、company、resume；不依赖mysqldump或账号密钥。

### 接口

`GET /jd-collector/api/postings/export.csv`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| keyword | String | 标题或原文 |
| direction/tier/stage | Enum[] | 可重复参数 |
| companyId | Long | 公司筛选 |

响应 `text/csv`，UTF-8 BOM，文件名 `jd-collector-yyyyMMdd-HHmm.csv`。非法参数 40001，生成失败 50001。



### 错误与完成标志

非法枚举/参数返回40001，文件生成失败50001；不能把失败响应保存成成功CSV。中文、逗号、双引号和多行文本需真实打开校验。输出19列及稳定排序以架构规则为准。

## 4. 验收方案

准备多档位、中文、引号和换行的测试JD；候选人检查Excel打开效果，Codex验证响应与条目过滤。所有P0通过，导出前后数据库不变；不建立Bruno集合。
