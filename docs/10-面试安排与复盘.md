# 面试安排与复盘

管理具体面试的日程、结果、问题和复盘，并同步[投递跟进](09-投递记录与跟进.md)；[计划看板](11-求职漏斗与计划看板.md)提供节点编辑弹窗，面试状态仍由interview领域维护。

## 1. 需求分析

### 背景、目标与对象

候选人需要管理已投岗位的轮次、日程、问题、反馈和结果，并让有效计划进入看板。

### v0.1 范围与核心需求

面试查询、新增、编辑、排期、完成、取消、爽约和复盘；排期同步岗位阶段与下一步。

### 边界、后台与兼容

未投递岗位不能创建面试；不做第三方日历、会议或推送；取消项以灰色历史节点保留在时间图。时间表面试节点负责维护和复盘，移除面试独立tab，旧路径返回时间表，旧七日字段仅接口兼容。

### 成功标准与工作量

多轮面试可追溯，排期/状态/看板一致且不重复，预计 1 日。

## 2. 架构设计

### 架构、规则与链路

```text
frontend/interview -> InterviewService -> jd_interview
posting/pipeline --------^校验/同步阶段----> jd_stage_event
dashboard <--------------^计划数据
创建SCHEDULED -> HR类型=HR_SCREEN，否则INTERVIEW -> 同步下一步 -> 看板
```

仅 `APPLIED/HR_SCREEN/WRITTEN_TEST/INTERVIEW/OFFER` 可创建；CANCELLED灰色历史节点，COMPLETED完成，NO_SHOW异常，同一面试同步动作去重。

### 数据模型

| 字段 | 类型 | 必填/约束 |
| --- | --- | --- |
| jobPostingId,roundNo | Long,Integer | 是；轮次≥1 |
| type | Enum | HR/TECHNICAL/MANAGER/FINAL/OTHER |
| format | Enum | ONLINE/ONSITE/PHONE |
| scheduledAt,status | DateTime,Enum | 是；SCHEDULED/COMPLETED/CANCELLED/NO_SHOW |
| interviewer,questions,feedback,nextStep | 120,Text,Text,500 | 否 |

### 目录与存储

图例：`[+]` 新增，`[~]` 修改，`[-]` 删除。
`backend/interview/src/main/java/com/jd/interview/{[~] ctrl,model,repo,service}`；`frontend/src/interview/{[~] api,pages,index.ts}`。`jd_interview` 由 JPA DDL 管理。

## 3. 开发方案

### 目标、依赖与顺序

交付日程和复盘：模型/Repo → 已投递校验及状态联动 → 接口 → 页面 → 看板联动。依赖 posting、pipeline、foundation。

### 接口与字段

| 方法/路径 | 请求 | 返回 |
| --- | --- | --- |
| GET `/jd-collector/api/interviews` | from、to（成对范围）、status、postingId | 面试列表 |
| POST `/jd-collector/api/postings/{id}/interviews` | 保存请求 | 新面试 |
| POST `/jd-collector/api/postings/{id}/interview-schedule` | expectedStage、scheduledAt、type、format必填，note≤500可选 | 自动分配轮次的新面试，供Pipeline记录反馈使用 |
| PUT `/jd-collector/api/interviews/{id}` | 保存请求 | 更新面试 |

保存请求：`roundNo/type/format/scheduledAt/status`必填，`interviewer≤120/questions/feedback/nextStep≤500`可选；响应增加 id、岗位/公司名和时间字段。错误：40001字段非法、40401不存在、40901岗位未投递或阶段不允许。

简化排期接口不接收投递简历和首次投递时间，使用岗位原始事实；轮次=该岗位未删除面试的最大轮次+1，状态固定SCHEDULED，备注存入面试nextStep。加岗位写锁并校验expectedStage，已有SCHEDULED面试时要求点击时间表原面试节点改期/补结果，不新增重复场次；未投递、已结束或OFFER阶段不能通过此入口新增面试。通用新增接口也取得同一岗位写锁。保存通过既有同步方法在同一事务中更新阶段、下一步与事件，看板直接聚合真实面试，不额外写计划表。

完成/取消本轮面试时只清理与该轮匹配的待办；旧轮次编辑不覆盖新轮次安排。编辑拒绝/接受/撤回/关闭后的历史面试不会重新激活岗位；已有另一场待面试时禁止重新置为SCHEDULED。

### 风险与完成

联动产生重复计划是主要风险，按 interviewId/同步动作去重。页面、阶段事件和时间图一致即完成。

## 4. 验收方案

### 范围与标准

验收排期、状态、复盘、阶段和看板联动；外部日历不验收。已有已投岗位，P0 全通过。

### 验收矩阵

| 编号 | 优先级 | 场景 | 前置 | 操作 | 预期 | 角色 |
| --- | --- | --- | --- | --- | --- | --- |
| INT-001 | P0 | 技术面 | APPLIED | 创建SCHEDULED | INTERVIEW且时间图出现 | 候选人 |
| INT-002 | P0 | HR面 | APPLIED | 创建HR | HR_SCREEN | Codex |
| INT-003 | P0 | 未投递 | SCREENED | 创建面试 | 40901 | Codex |
| INT-004 | P0 | 完成复盘 | 已排期 | 填问题反馈并完成 | 保存且标完成 | 候选人 |
| INT-005 | P0 | 取消/爽约 | 已排期 | 更新状态 | 取消隐藏、爽约异常 | 候选人 |
| INT-006 | P0 | 去重 | 已同步下一步 | 看看板 | 同一面试仅一项 | Codex |

### 分工与记录

候选人验收页面/复盘，Codex 验证接口/联动。记录环境、时间、API、页面、数据、问题、结论。
