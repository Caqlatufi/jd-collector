# 数据备份与恢复

负责本地求职业务数据库及历史账号密钥的配套备份、独立库恢复核对。CSV另见[JD筛选导出](13-JD筛选导出.md)；平台当前登录态由Electron维护，数据库备份不等于浏览器会话备份。具体运行命令仍统一维护在[AGENTS.md](../AGENTS.md)。

## 1. 需求分析

### 目标、对象、范围

防止本机求职数据丢失，由Codex执行受控备份与恢复，候选人确认需要恢复的时间点和目标。备份覆盖当前全部业务表及存在的历史账号配套密钥，恢复首先在独立临时库核对。

| 范围 | 规则 |
| --- | --- |
| 数据库 | 本地dump文件，不以CSV代替完整关系数据 |
| 历史账号密钥 | 存在时与SQL同批保存，不生成新密钥替代旧密钥 |
| 恢复验证 | 独立空库，核对表、关键行数、引用和唯一启用Master |
| 恢复授权 | 不覆盖使用中数据库；真实恢复单独确认目标与停机范围 |
| 不建设 | 云备份、定时调度、远程同步、图形恢复后台或新增HTTP接口 |
| 不承诺 | 当前脚本不包含Electron userData和截图证据，不能用dump恢复站内登录态或图片文件 |

历史账号数据保持只读兼容；是否有密钥与“当前Electron已登录”没有因果关系。成功标准为非空备份及独立库可恢复、配套密钥哈希一致，不只看脚本退出码。

## 2. 架构设计

### 数据流与归属

```text
MySQL业务表 ────────→ 本地dump SQL ───→ 独立临时恢复库
历史master.key ─────→ 同时间戳.accounts.key
ops/backup.ps1       负责上述文件配对与SHA-256核对
Electron userData    独立登录态存储，不在当前dump范围
runtime/captures     独立图片证据，不在当前dump范围
```

备份脚本归ops，产物归被Git忽略的backups；不创建业务表、模型或迁移。秘密不出现在源码、响应、对话和日志摘要。恢复一致性以当前业务表及引用为单位，不按代码模块各备一份造成不同时点拼装。

## 3. 开发方案

### 现有实现与参数

ops/backup.ps1从本机配置读取数据库凭据，生成带时间戳SQL；备份成功后复制runtime/accounts/master.key到同时间戳.accounts.key，并比较SHA-256。自定义密钥路径使用-AccountKeyPath；未配置账号且密钥尚未生成时提示无密钥，不能伪造配套文件。

SQL与密钥必须配套保留。恢复历史密钥时使用原配置位置，不能用新密钥代替；此举不重新开启Java浏览器或解密功能。文件生成、非空检查和配套哈希结果均需核对，失败明确停止并报告。

### 恢复与风险控制

先选定具体备份、验证源文件，再恢复到独立空库，核对jd_company、jd_resume_version、jd_posting、jd_stage_event、jd_interview、jd_resume_content_block、jd_platform_account及关键关联。以实际当前业务表为准，新增业务表时同步更新恢复清单。

正式恢复前按AGENTS停止应用，核对目标库、保存当前库备份，经用户明确授权后才切换/恢复；严禁覆盖运行中数据库。恢复后检查健康接口、关键页面、唯一启用Master和投递引用。本次整理不执行上述恢复操作。

数据库恢复不会恢复Electron userData或runtime/captures；若需要完整机器迁移，需另确认这些文件范围，不在此处假装已有全机备份能力。

## 4. 验收方案

准备可恢复SQL、独立临时空库及可选历史密钥；Codex验证备份与恢复，用户确认正式恢复目标。全部P0通过；不能把密钥复制成功当作完整恢复已通过。

| 编号 | 优先级 | 场景 | 前置条件 | 操作 | 预期结果 | 责任角色 |
| --- | --- | --- | --- | --- | --- | --- |
| EXP-004 | P0 | 全库备份 | 数据库可用 | 执行备份 | 文件非空、退出码0 | Codex |
| EXP-005 | P0 | 恢复 | 独立空库 | 导入并核对 | 当前所有业务表及关键行数一致 | Codex |
| EXP-007 | P0 | 账号密钥备份 | 存在密钥 | 执行备份 | 同时间戳 SQL 与密钥文件，源/目标哈希相同 | Codex |

### 验证说明

个人数据库操作、真实岗位样本与历史验收证据保存在本地 `local/private-docs/`。公开仓库的测试使用隔离夹具；实际验证范围以测试输出为准。
