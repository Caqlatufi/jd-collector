# JD门槛填写

## 一、需求分析

### 背景与目标

个人筛选条件原为根目录 Markdown 问卷，不便逐项填写。将其转换为结构化 JSON，在工作台提供中文分组表单，用户填写、Agent 读取同一来源。已有明确条件保留，补充建议不能冒充用户决定。

### 范围与成功标准

| 内容 | 本期边界 | 成功标准 |
| --- | --- | --- |
| 数据转换 | 保留已有答案、提示、证据及操作边界；旧文件先备份 | 默认 `local/JD门槛.json` 作为有效门槛来源 |
| 门槛表单 | 4 组、20 个主要问题，单选项及每题末尾“其他”自由填写 | 允许部分填写；保存即采用答案，刷新后内容不丢 |
| 入口导航 | 从 JD 列表操作区“JD门槛”按钮进入，不设一级菜单 | 查看门槛时高亮 JD 列表，独立路由仍可直达 |
| 文件维护 | 项目local/ 下的 JSON 是唯一来源，不建数据库副本 | 页面保存后 Agent 可直接读取同一文件 |
| 保护 | 版本冲突、写入异常、未保存离开提醒 | 不静默覆盖外部修改，不把失败显示为成功 |

不包含：自动理解答案、自动评分公式、既有岗位重评/删岗/投递、工作台登录鉴权、Electron 会话变更。用户已要求实施，不新增审批步骤。

## 二、架构设计

```text
app 入口挂载
├─ frontend/src/criteria：分组表单、保存状态和离开提醒
└─ backend/criteria（com.jd.criteria）：文件读取、校验和持久化
   ├─ 本地 local/JD门槛.json：唯一有效数据源，Agent 同步读取
   └─ backups/criteria：每次保存前的旧版本（本机忽略目录）
```

### 关键规则与职责

- 已确认且非空的答案才作为本人门槛；待确认及空白不表示接受，也不表示排除。规则性质区分硬门槛、偏好、核验等，不从数值自动推断。
- 不让用户逐项配置性质或勾选确认；保存时有内容的答案标为 CONFIRMED，空白标为 PENDING。迁移保留旧答案和状态，旧版已填写未确认的内容由用户下一次保存统一采用。
- 表单可以只保存一部分答案；保存不调用 JD、Pipeline 或招聘平台接口。
- 文件中的分组、选项、字段身份和说明由 JSON 维护。页面只让用户选择或填写答案，内部兼容 kind/status 数据，不把它们作为额外问卷。分组不是后端业务模块。
- 基础条件移到 baselineRules，仍是已知筛选前提；采集证据边界保留在 agentNotes，不作为表单题目。删除未填的复杂薪资换算、分项评分、配额和核验细则。已填写内容逐字保留，无法匹配选项时回显到“其他”，不擅自改写或拆分。
- 同一服务串行保存，SHA-256 版本核对后，先备份再原子替换。原子替换不支持则明确失败，不退化为不安全覆盖。外部 Agent 编辑也应先读取最新文件，避免与页面并行写入。
- 无 Electron 业务代码，无浏览器缓存副本，无数据库迁移。
- JD 列表只提供跳转入口；门槛表单和存储仍属于独立 criteria 模块，不合并业务实现。

## 三、开发方案

### 模块与接口

| 位置 | 内容 |
| --- | --- |
| `frontend/src/criteria` | 路由 `/criteria`、模块 API、模型、填写页面 |
| `backend/criteria` | CriteriaConfig、Controller、DTO、Service |
| app 挂载 | Gradle settings/app 依赖、Config 导入、SpaController 直达路径；Vue main 安装，路由 meta.activeMenu 指向 /postings；JD 列表按钮跳转 /criteria |
| 文档约定 | 根 AGENTS 指向 JSON，docs 索引增加本功能 |

实际路径带上下文 `/jd-collector`，响应沿用 `code/msg/result`。

| 方法与路径 | 请求 | 结果 |
| --- | --- | --- |
| GET `/api/criteria` | 无 | `revision` 与 `document` |
| PUT `/api/criteria` | `revision`、完整 `answers` 数组 | 保存后的版本与文档 |

`document` 含 `schemaVersion=1`、`formVersion=2`、title、description、baselineRules、agentNotes、sections；section 含 id/title/notes/fields；field 含 id/label/value/hint/kind/status，以及字符串数组 options。value 可为 null，status 为 PENDING/CONFIRMED。每条答案仅含 id/value/kind/status；不允许修改标签、选项、基础条件或结构。

选项按 JSON 顺序展示，最后统一添加“其他”；未匹配选项的原答案自动按其他文本回显。选择标准答案保存其原文，选择其他保存自由文本；未选或其他空白保存 null。切换选项可暂存本页的其他草稿，点击“清空”撤销本题答案。旧 JSON 先备份并核对版本后再精简，不用空模板覆盖已填答案。

请求校验：版本格式、字段 ID 完整且唯一、未知 ID、答案最大 10000 字、性质最大 50 字、状态枚举、已确认答案非空；拒绝不支持的文件版本或损坏结构。400 表示无效输入，409 表示版本冲突，500 表示文件不可用/不可写。失败时保留页面输入，用户选择重载才放弃。

配置 `jd-collector.criteria-file` / `JD_COLLECTOR_CRITERIA_FILE` 可显式指定路径；相对路径以项目根为基准。未设置时定位项目根并读取 `local/JD门槛.json`（兼容根目录启动及 backend/app 开发启动），找不到则请求明确报错，不生成空默认值。`ops/init-local.ps1` 从 `config/criteria.example.json` 复制无个人答案的本地副本，不覆盖已有文件。Agent 通过 GET `/api/criteria` 读取实际有效配置，不能把示例当个人答案。备份在文件同级 `backups/criteria`，临时文件与目标同目录。

先转换文档并备份，再实现文件 API 和表单，最后测试和本地部署。只重启 Java 服务加载新包；不关闭 Electron、不重载外站。

## 四、验收方案

### 环境与责任

助手执行隔离自动测试与本地只读检查，用户确认实际筛选答案。服务测试使用临时文件，不覆盖本人 JSON；浏览器保存测试模拟接口，禁止未匹配写请求进入个人服务。真实 HTTP 测试使用独立随机端口和临时文件。

| 编号 | 优先级 | 场景/操作 | 预期结果 |
| --- | --- | --- | --- |
| CR-001 | P0 | 精简原问卷 | 4 组、20 题，7 条本人已填答案逐字保留；13 条基础条件及采集证据边界继续保留，旧版可从备份恢复 |
| CR-002 | P0 | 直达/刷新 `/criteria` | 页面可用，读到真实 JSON，不误用数据库或缓存 |
| CR-003 | P0 | 编辑并保存部分答案，再读取 | UTF-8 文件持久化，空白仍可保留，确认状态正确 |
| CR-004 | P0 | 新版本保存后再提交旧版本 | HTTP 409，文件和页面未保存输入不被覆盖 |
| CR-005 | P0 | 重复/缺失/未知字段 ID 或无效确认 | HTTP 400，文件不变 |
| CR-006 | P0 | JSON 缺失、损坏、版本不支持 | 明确失败，不生成空文件，不回退伪造默认值 |
| CR-007 | P0 | 保存或备份失败 | 失败结果，不返回成功，不覆盖已有有效文件 |
| CR-008 | P1 | 修改答案、离开/刷新 | 未保存导航可取消，输入保留；保存后有答案即确认，清空后待填写 |
| CR-009 | P1 | 四组题目、720/1000 竖屏 | 选项可换行，每题有“其他”；不再显示性质选择、确认勾选或待确认筛选 |
| CR-010 | P0 | 保存后的备份核对 | 备份等于前版本，当前文件等于新版本 |
| CR-011 | P0 | 保存门槛 | 不触发评分、投递、跟进及平台会话变化 |
| CR-012 | P0 | 从 JD 列表点击“JD门槛”，刷新及返回 | 顶部无门槛菜单；进入独立填写页，JD 列表保持高亮，返回列表正常 |
| CR-013 | P0 | 标准选项、其他文本、切换及清空 | 保存重读一致；不匹配的旧答案原样显示在其他中，不预选未答题 |

执行结果在交付时汇报，不把计划场景当作已验收。不新增 Bruno 或增量需求流水。
