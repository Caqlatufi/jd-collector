# 投递记录与跟进

从用户记录实际投递开始，管理阶段、下一步和历史事件；未投递JD仍留在[JD列表](05-JD管理与评分.md)，不自动生成明日跟进。该功能不向招聘网站自动发送简历。

## 1. 需求分析

### 背景、目标与对象

Pipeline 应从真实投递开始，让候选人追踪简历、时间、阶段、任务和历史，而不是把所有已筛选 JD 当待办。

### v0.1 范围与核心需求

JD 列表投递、阶段推进、下一步维护、事件历史；只展示 `APPLIED` 及后续有效岗位。

### 本期边界与能力边界

不执行外部投递，不创建面试明细，不为无任务岗位虚构时间；`TO_CONTACT/READY_TO_APPLY` 仅兼容旧数据。

### 后台、兼容、成功与工作量

Pipeline 页推进已投岗位并查看事件，JD 页承担首次投递。快照和事件事务一致、无投递不入池、无任务不显示计划即达标，预计 1 日。

## 2. 架构设计

### 架构与链路

```text
JD投递按钮 -> PipelineService -> jd_posting 当前快照
                           └----> jd_stage_event 追加历史
resume --------------------------^ 版本校验
interview/dashboard <------------^ 状态与计划
```

### 规则矩阵

| 规则 | 口径 |
| --- | --- |
| 起点 | SCREENED 点击投递后 APPLIED |
| 投递必需 | resumeVersionId + appliedAt |
| 下一步 | 动作/时间成对或同时为空 |
| 结束 | ACCEPTED/REJECTED/WITHDRAWN/CLOSED 清空下一步 |
| 事件 | 阶段变化追加，事务失败整体回滚 |

### 模型、流程与目录

`jd_stage_event`：`jobPostingId:Long`必填、`fromStage:Enum?`、`toStage:Enum`必填、`occurredAt:DateTime`必填、`note:String(1000)?`。当前快照在 `jd_posting`。

```text
投递校验 -> 更新快照 -> 追加事件 -> 看板可见
阶段推进 -> 校验下一步 -> 更新/清空 -> 追加事件
backend/pipeline/src/main/java/com/jd/pipeline/{[~] ctrl,event,model,service}
frontend/src/pipeline/{[~] api,pages,index.ts}
```

图例：`[+]` 新增，`[~]` 修改，`[-]` 删除。实体由 JPA DDL 管理。

## 3. 开发方案

### 目标、范围、依赖与顺序

交付首次投递、推进和事件：Stage 模型 → 事务 Service → 接口 → JD 投递弹窗 → Pipeline 页面。依赖 posting、resume、foundation。

### 接口与数据

`PUT /jd-collector/api/postings/{postingId}/stage`

| 字段 | 类型 | 必填/规则 |
| --- | --- | --- |
| toStage | Stage | 是 |
| resumeVersionId | Long | 投递及后续必需 |
| occurredAt | DateTime | 否，默认当前 |
| appliedAt | DateTime | 投递及后续必需 |
| nextAction/nextActionAt | String(500)/DateTime | 成对或都空 |
| note | String(1000) | 否 |

返回完整岗位。`GET /jd-collector/api/postings/{id}/events` 返回 `id/fromStage/toStage/occurredAt/note` 列表。

错误：40001 字段非法，40401 岗位/简历不存在，40901 SKIP投递、缺前置或下一步不成对。

### 页面、风险与完成

JD 页首次投递；Pipeline 只显示已投及后续，CLOSED 不作待跟进卡片。事务半成功是核心风险，必须由同一事务覆盖。真实投递可追溯且无虚假计划即完成。

## 4. 验收方案

### 范围、前置与标准

验收首次投递、阶段推进、事件事务、下一步和结束状态；外部招聘网站操作不验收。JD 和启用简历已存在，P0 全通过。

### 验收矩阵

| 编号 | 优先级 | 场景 | 前置 | 操作 | 预期 | 角色 |
| --- | --- | --- | --- | --- | --- | --- |
| PIP-001 | P0 | 首次投递 | SCREENED | 选简历和时间 | APPLIED并追加事件 | 候选人 |
| PIP-002 | P0 | 缺简历 | SCREENED | 不选简历投递 | 40901且不变 | Codex |
| PIP-003 | P0 | SKIP投递 | SKIP岗位 | 点击投递 | 拒绝且不入Pipeline | Codex |
| PIP-004 | P0 | 无任务 | 已投递 | 动作时间都清空 | 成功且看板不显示 | 候选人 |
| PIP-005 | P0 | 不成对 | 已投递 | 只填一项 | 40901且不变 | Codex |
| PIP-006 | P0 | 结束 | 进行中 | 推进CLOSED | 下一步清空 | 候选人 |
| PIP-007 | P0 | 回滚 | 制造事件失败 | 推进 | 快照和事件都不变 | Codex |

### 分工与记录

候选人验收页面，Codex 验证真实 HTTP、事务和数据。记录环境、时间、API、页面、数据库、问题、结论。
