# 投递记录与跟进

从用户记录实际投递开始，管理阶段、下一步和历史事件；未投递JD仍留在[JD列表](05-JD管理与评分.md)，不自动生成明日跟进。该功能不向招聘网站自动发送简历。

## 1. 需求分析

### 背景、目标与对象

Pipeline 应从真实投递开始，让候选人追踪简历、时间、阶段、任务和历史，而不是把所有已筛选 JD 当待办。

### v0.1 范围与核心需求

JD 列表投递、阶段推进、下一步维护、事件历史；只展示 `APPLIED` 及后续有效岗位，以及保留实际投递时间的关闭历史。

Pipeline行内“记录反馈”替代通用推进表单。APPLIED/HR_SCREEN/WRITTEN_TEST只提供“安排面试”和“初筛不通过”：面试只必填已约定时间，类型/形式默认技术面/线上并可展开修改，轮次由后端自动计算；不通过只确认结果，原因选填。移除简历版本、首次投递时间、目标阶段、自由下一步动作/时间的重复编辑，不读取启用简历列表。已投递简历版本及首次投递时间沿用原始事实。

INTERVIEW阶段显示安排下一轮、收到Offer、面试未通过；OFFER显示接受/放弃；结束岗位不再显示反馈按钮。面试改期和复盘从行内“面试记录”进入原面试模块。后续安排为空时显示等待反馈，结束显示已结束；已有跟进内容仍可查看。

Pipeline 顶部支持公司或岗位名称的包含匹配，忽略首尾空格和英文字母大小写，搜索不匹配 JD 正文。搜索与阶段、方向、等级筛选组合使用，阶段汇总按当前名称搜索结果计数。读取全部分页后筛选，避免超过 100 条时漏掉投递记录。无匹配时提示调整搜索或筛选条件。

从 JD 列表点击已投递阶段文字，进入 `/pipeline?keyword=岗位名称&postingId=岗位ID`，搜索框自动回填且精确显示该岗位；刷新保留名称、阶段与定位条件。修改或清空搜索会解除岗位 ID 定位，按名称展示所有匹配的已投递岗位。“查看全部岗位”清空搜索与筛选。原计划时间图的 `postingId` 直达入口继续兼容。

首次“记录投递”弹窗只保留实际使用简历、实际投递时间和投递备注；移除下一步动作、下一步时间及相关成对校验，提交时不携带 `nextAction/nextActionAt`。定时跟进功能后续再设计，本次不增加自动跟进任务。已有 Pipeline 跟进数据与接口保持兼容。

### 本期边界与能力边界

不执行外部投递；安排面试通过interview模块创建真实面试明细并同步阶段和时间图，不为未约定时间虚构排期；`TO_CONTACT/READY_TO_APPLY` 仅兼容旧数据。

### 后台、兼容、成功与工作量

Pipeline页记录已投岗位反馈并查看事件，JD页承担首次投递。快照、面试和事件事务一致，投递自动进入进度时间图，未投递不入池。

## 2. 架构设计

### 架构与链路

```text
JD投递按钮 -> PipelineService -> jd_posting 当前快照
                           └----> jd_stage_event 追加历史
resume --------------------------^ 版本校验
interview/dashboard <------------^ 状态与计划
```

### 规则矩阵

| 规则 | 口径 |
| --- | --- |
| 起点 | SCREENED 点击投递后 APPLIED |
| 投递必需 | resumeVersionId + appliedAt |
| 下一步 | 动作/时间成对或同时为空 |
| 结束 | ACCEPTED/REJECTED/WITHDRAWN/CLOSED 清空下一步 |
| 事件 | 阶段变化追加，事务失败整体回滚 |

### 模型、流程与目录

`jd_stage_event`：`jobPostingId:Long`必填、`fromStage:Enum?`、`toStage:Enum`必填、`occurredAt:DateTime`必填、`note:String(1000)?`。当前快照在 `jd_posting`。

```text
投递校验 -> 更新快照 -> 追加事件 -> 看板可见
阶段推进 -> 校验下一步 -> 更新/清空 -> 追加事件
backend/pipeline/src/main/java/com/jd/pipeline/{[~] ctrl,event,model,service}
frontend/src/pipeline/{[~] api,pages,index.ts}
```

图例：`[+]` 新增，`[~]` 修改，`[-]` 删除。实体由 JPA DDL 管理。

时间表同时提供进度推进、投递日期纠正和历史节点编辑；投递日期纠正校验expectedAppliedAt并只更新appliedAt，阶段历史编辑校验事件归属及expectedOccurredAt，仅更新时间和备注。

## 3. 开发方案

### 目标、范围、依赖与顺序

交付首次投递、推进和事件：Stage 模型 → 事务 Service → 接口 → JD 投递弹窗 → Pipeline 页面。依赖 posting、resume、foundation。

### 接口与数据

`PUT /jd-collector/api/postings/{postingId}/stage`

| 字段 | 类型 | 必填/规则 |
| --- | --- | --- |
| toStage | Stage | 是 |
| resumeVersionId | Long | 投递及后续必需 |
| occurredAt | DateTime | 否，默认当前 |
| appliedAt | DateTime | 投递及后续必需 |
| nextAction/nextActionAt | String(500)/DateTime | 成对或都空 |
| note | String(1000) | 否 |

返回完整岗位。`GET /jd-collector/api/postings/{id}/events` 返回 `id/fromStage/toStage/occurredAt/note` 列表。

`PUT /jd-collector/api/postings/{id}/result`：expectedStage、result必填，note≤1000可选。不接收简历、首次投递时间或自由跟进字段；加岗位写锁并校验当前阶段。初筛阶段只允许REJECTED，面试允许REJECTED/OFFER，Offer允许ACCEPTED/WITHDRAWN。已投岗位的历史简历即使归档也沿用，不要求重新选择。已投后SKIP仍允许记录实际结果；首次投递的SKIP拦截保留。失败不追加事件或改写快照，成功追加带“初筛不通过/面试未通过/收到Offer/接受Offer/放弃Offer”的事件，结束清空旧跟进。

安排面试使用[面试模块简化排期接口](10-面试安排与复盘.md)，面试明细、阶段、下一步和事件在同一事务中保存；重复保存、旧阶段和已有未完成面试均返回409，不生成重复轮次。

错误：40001 字段非法，40401 岗位/简历不存在，40901 SKIP投递、缺前置或下一步不成对。

### 页面、风险与完成

JD 页首次投递；Pipeline 只显示已投及后续，保留投递时间的 CLOSED 可查看历史，不作待跟进卡片。事务半成功是核心风险，必须由同一事务覆盖。真实投递可追溯且无虚假计划即完成。
