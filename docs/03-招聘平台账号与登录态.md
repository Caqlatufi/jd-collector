# 招聘平台账号与登录态

本功能只负责招聘平台入口、在站内登录、登录态延续和失效接续；不负责JD列表识别、截图协议、模型Prompt、评分或归档。后者单独维护在[JD采集与截图识别](04-JD采集与截图识别.md)。本地工作台仍为单用户，不建设自己的登录鉴权。

## 1. 需求分析

### 背景、对象与目标

候选人只需在JD Collector内置平台页面登录，之后向Agent描述岗位条件；不再手动配置账号密码、获取会话、检查登录、选择标签或点击读取岗位。账号维护指平台入口及登录会话维护，不是另建一个平台密码管理器。

### 范围与边界

| 需求 | 规则与完成口径 |
| --- | --- |
| 平台入口 | BOSS直聘、猎聘、前程无忧、智联招聘四张卡；拉勾保持停用，排列不代表市场排名 |
| 打开/返回 | 已有同平台页则返回，不重载当前岗位；没有则在内置标签打开 |
| 登录 | 扫码、短信、密码和验证码均由本人在平台网页完成；不把凭据交Agent或Java |
| 登录态维持 | 同平台主域、子域及新标签沿用既有持久分区；切页与正常重启不主动清除会话 |
| 失效接续 | 过期或平台要求验证时暂停后续采集，用户在原平台页处理；不自动验证码、不承诺永不过期 |
| 状态表达 | 加载状态、页面可读性与认证状态分开；页面ready、Cookie数量、头像或公开JD不足以证明已登录 |
| 网页模式 | 明确提示使用桌面客户端，不启动独立Chrome、不承诺继承普通浏览器session |
| 历史兼容 | Java账号密文与本地历史密钥只读保留；不回填Electron、不作为当前身份凭证 |

账号页仅提供平台卡片、打开/返回和页面打开状态。登录状态的当次判断由Agent依据实际页面证据完成；不恢复账号配置、检查登录或读取结果面板。本功能不新增数据库字段、远程同步或定时自动登录。

候选人负责登录和身份验证，Codex负责平台入口、分区兼容与状态边界验证。成功标准为能返回原平台页、正确复用/隔离会话、失效可接续；不能以打开页面成功代替认证成功。账号入口沿用现有实现维护，不把采集识别3–5天估算重复计算到本功能。

## 2. 架构设计

### 功能链路

```text
/accounts平台卡片 → common公共请求/事件 → app装配 → 平台WebContentsView
                                                    └─ 固定平台persist分区
用户在网站登录 ────────────────────────────────────────┘
Agent观察当前页
├─ 有明确认证证据 → 交采集功能继续
├─ 登录/验证要求 → 停止采集，用户接续
└─ 证据不足 → UNKNOWN，不冒称成功
backend/account → 历史账号只读兼容（与Electron身份无同步链路）
```

### 归属和模型

| 对象 | 归属与规则 |
| --- | --- |
| 平台定义 | frontend/src/account/adapters/platforms.ts；纯配置，含平台代码、入口域与分区 |
| 平台卡片 | frontend/src/account/pages/AccountsPage.vue；订阅公共事件，卸载取消 |
| 标签容器 | common/desktop/main；key标识页面，sessionKey标识共享会话，详见桌面浏览器文档 |
| 认证判断 | Agent当次页面证据；不是持久化的“永远已登录”标记 |
| 历史记录 | backend/account与jd_platform_account；只读兼容，不解密/迁移/清除旧数据 |
| 登录数据 | Electron本机userData；不进入Git、HTTP响应、截图识别输入或日志 |

```text
frontend/src
├─ account/pages/AccountsPage.vue       平台入口
├─ account/adapters/platforms.ts        平台身份、域、持久分区
├─ app/electron/main.ts                 装配平台配置
└─ common/desktop/main                  通用标签与session生命周期
backend/account                         历史只读兼容
```

业务代码继续通过公共请求与事件解耦，不导入Electron/Node、不反向依赖app。外站不加载工作台preload。物理代码可以由多个功能复用，文档不因此合并。

## 3. 开发方案

### 入口与状态契约

账号页复用现有平台列表/打开和公共浏览器事件，不增加登录HTTP端点。platform.list/open与platform.changed的具体类型以frontend/src/common/desktop/platform.ts为准；本功能不恢复inspect/read的岗位正文用途。

| 平台代码 | 固定sessionKey | 入口域 |
| --- | --- | --- |
| BOSS | www_zhipin_com | zhipin.com及已注册子域 |
| LIEPIN | www_liepin_com | liepin.com及已注册子域 |
| JOB51 | www_51job_com | 51job.com及已注册子域 |
| ZHAOPIN | www_zhaopin_com | zhaopin.com及已注册子域 |

打开输入为受支持的平台代码；内部复用活跃同平台标签，否则首个同平台标签，均不重新导航。没有现存页才创建。返回的key、加载状态与脱敏URL只说明页面状态。browser.changed还包含title、active、canGoBack、canGoForward等，完整公共字段见[桌面契约](02-桌面浏览器与多标签.md#3-开发方案)。

| 认证语义 | 处理 |
| --- | --- |
| EVIDENCED | 仅当次页面有明确证据，不承诺后续仍有效 |
| LOGIN_REQUIRED | 用户在原页登录，Agent暂停采集 |
| VERIFICATION_REQUIRED | 用户完成验证码/身份验证，不自动处理 |
| UNKNOWN | 继续如实标未知；公开JD可读不等于登录 |

上述为视觉流程的Agent判断语义，不表示账号页新增了检查按钮或后端认证状态表。当前旧适配代码的LoginStatus仍为VERIFIED/NEEDS_LOGIN/NEEDS_VERIFICATION/UNKNOWN，不能把目标视觉协议当作已实现接口；采集协议如何传递状态见独立采集功能。

### 历史接口与错误

GET /jd-collector/api/accounts仅返回历史兼容信息，不返回密码、Cookie、Token、密文或当前Electron身份。旧账号写操作继续HTTP400/code40002，不恢复Java浏览器或Playwright依赖；不解密历史快照。网页模式明确DESKTOP_UNAVAILABLE；标签关闭、加载失败或延迟空白不能继续显示已登录。

### 实施与维护边界

沿用原sessionKey，切换卡片布局不能创建新分区导致用户被动退出。平台规则由account提供、app注入、common执行。用户登录时不重启或清理其客户端。普通退出保持持久化数据，未保存页面输入不承诺跨退出恢复。

历史密钥配套备份见[数据备份与恢复](14-数据备份与恢复.md)；数据库dump不等于Electron会话备份。截图、原生受限输入、子Agent调度和归档均在采集识别文档开发方案内定义。

## 4. 验收方案

### 范围与标准

使用独立userData和本地站点夹具验证共享、隔离和重开；真实平台另由用户登录后验证。账号入口、网页降级和旧接口兼容全部P0通过；不以本地夹具证明真实平台认证，也不宣称长期免登录。Codex验证请求、事件与旧接口响应，用户负责实际身份验证。

### 验收矩阵

| 编号 | 优先级 | 场景 | 前置条件 | 操作 | 预期结果 | 责任角色 |
| --- | --- | --- | --- | --- | --- | --- |
| VIS-001 | P0 | 平台卡片 | 桌面工作台 | 查看四卡并打开/返回 | 无选择标签、读取、检查登录、预览；复用已有页 | Codex |
| VIS-002 | P0 | 网页降级 | 普通浏览器 | 打开账号页 | 明确桌面入口，不拉起独立Chrome | Codex |
| VIS-106 | P0 | 登录与验证码 | 认证页 | 主Agent审图 | 停止岗位识别，由本人完成，不发送认证内容 | Codex+用户 |
| VIS-107 | P0 | 状态未知 | 只有头像或公开岗位 | 判断登录 | 保持UNKNOWN，不把页面可读当已登录 | Codex |
| VIS-208 | P0 | 兼容 | 旧账号密文与原分区 | 重启/调用旧接口 | 会话分区不换；旧写400/40002，秘密不变 | Codex |

会话容器基础用例FND-105、FND-111、FND-112由[桌面浏览器验收](02-桌面浏览器与多标签.md#4-验收方案)承接，本功能验证其平台注册分区含义。VIS-106/107同时是采集开始前的认证停点，不将登录/验证图片分发给JD识别子Agent。

### 验证说明

个人数据库操作、真实岗位样本与历史验收证据保存在本地 `local/private-docs/`。公开仓库的测试使用隔离夹具；实际验证范围以测试输出为准。
