## 如何维护

个人门槛填写见 [JD门槛填写](15-JD门槛填写.md)：分组表单、JSON 持久化与确认状态；不自动评分、投递或修改已有 JD。有效规则通过 criteria API 读取，默认保存在 `local/JD门槛.json`；[公开示例](../config/criteria.example.json)不含个人答案。JD之间的三档知识词与加权共现关系见[JD知识图谱](16-JD知识图谱.md)。

- 按用户要完成的主功能确定文档归属，不按`backend`或`frontend/src`目录决定一份文档的边界；同一代码模块可以支撑多个功能。
- 新增主功能才增加文件；已有需求变化直接更新对应功能的四个章节。跨功能改动分别更新各自边界，通过链接引用契约，不复制完整规则。
- 账号与登录态只保证平台入口及认证接续；采集识别消费页面并生成复核候选；JD管理保存岗位与评分；记录实际投递之后才进入Pipeline。
- 不新建模块子目录、四份独立阶段文件、项目总架构、研究目录或按日期追加的开发流水。运行维护统一见[根AGENTS](../AGENTS.md)。
- 代码仍保持独立模块挂载；文档平铺不授权代码合并、数据库迁移、会话清理或运行服务变更。
- 保留既有验收编号，历史记录不当作本次重跑。截图原生能力仍待实现，Astra/medium共享Prompt已编写；完整视觉归档链路尚未验收。详见采集识别文档。
- 本地工作台不建设自身登录鉴权，不维护Bruno集合。
