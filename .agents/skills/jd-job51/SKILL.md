# 前程无忧岗位 workflow

## 入口与边界

项目：`项目根目录`。先读取项目 AGENTS.md 及本 Skill 的 [公共操作规则](../platform-workflow.md)，按其顺序执行；不要要求用户操作“读取标签”。
平台代码：`JOB51`；官方主站：`https://www.51job.com/`。
领域适配：`frontend/src/account/adapters/platforms.ts` 中本平台配置；共享原生执行由 app 装配，不把 Electron 导入业务模块。

识别核心统一为 `gpt-6-astra` / `medium`；进行图片识别时完整读取 [标准Prompt](../jd-vision-prompt.md)。原生 capture/scroll/click/type 已接入；使用公共操作规则中的命令取图，不退回旧 DOM 读取。

## 本平台步骤

1. 在项目 frontend 运行 `node src/app/electron/workflow.mjs JOB51 open`，再 `JOB51 tabs` 确认页面。
2. 若用户本轮只要求登录，保持页面打开交给本人，不擅自采集。本人登录/验证完成后才继续需要认证的操作。
3. 区域搜索先读 本地 `local/JD搜索任务单-前程无忧.md`（未建立时参考 [任务单示例](../../../config/search-task.example.md)），按公共规则设置并截图核验地点、经验、薪资、规模及工作安排，再浏览列表。经验主搜与补搜档位以本地门槛和任务单为准；平台档位以当前页面为准，未支持的条件明确记缺口。公开官方域链接只作补充线索，不使用第三方摘要替代真实原文。
4. 用 `JOB51 navigate "<已核实的官方岗位URL>" [key]` 定位，`JOB51 tabs` 确认目标；focus 明确目标后 capture 取得原生图片，再交 Astra/medium 按标准 Prompt 识别。URL 必须属于本平台注册域；不编造搜索 API 或绕过验证。
5. 按公共规则核对后，只在用户授权采集/更新时走现有 JD HTTP 接口。报告链接、时间、缺口和已保存数量。

## 本平台真实性

原生截图、受限输入和旧 DOM 退役已实现。2026-09-09 已执行本平台真实详情 → Astra/medium → 主 Agent 对图复核 → 独立 H2 的真实 HTTP 保存、来源查重及状态回读。结果仅代表该样本与当次页面，不代表全站搜索覆盖、长期认证或所有岗位符合门槛。遇到登录、验证码、空页或无法辨识的图，停止相应操作交本人处理。

## 视觉操作要点

- 已验证在搜索框输入 Java、提交搜索并选择配置的城市/区域，再打开独立详情；每步截图核对效果。
- 搜索站可能是 we.51job.com，详情是 jobs.51job.com；共享原分区，来源保存实际详情 URL。
- 微信二维码浮层和窄窗可能遮挡正文右边；优先适当扩大窗口，否则同一纵向段横向补图并保留重叠，不以读到文末冒称完整。
- 公司全称可能位于正文之后的“公司信息”，具体办公室位于“工作地址”；薪资“万”与实际薪数原样保留。
